# Implementation coverage

This table distinguishes implemented behavior from work that still needs integration or domain validation. The application does not claim that syntax inspection reconstructs every business rule or runtime architecture.

| Requirement area | Implemented | Current limit |
| --- | --- | --- |
| GitHub access | Public access, encrypted PATs, OAuth with state/PKCE, user/organization repository pagination, branches/tags and commit resolution | OAuth refresh and GitHub App installation flows are not implemented; live authentication needs account validation |
| Source retrieval | Read-only fixed-commit archives, trusted redirect host, no credential forwarding, path/symlink/size checks, temporary cleanup | Submodules and LFS content are not retrieved; GitHub.com only |
| Analysis | Python AST, Tree-sitter JS/TS/Java/Go declarations, Python route/schema/guard extraction, JS route heuristics, manifest dependencies, local import graph, test/deployment inventory | No complete interprocedural analysis; Ruby/Rust/C#/PHP primarily inventory and manifests; dynamic imports and aliases can remain unresolved |
| Business logic | Code-backed guards, function documentation, validation constraints; optional evidence-constrained LLM synthesis | Business intent, actual user roles and application workflows require human review |
| API/database | Python endpoint decorators and annotations, common JS route calls, Python model/schema constraints and SQL table declarations | Middleware, router mount prefixes, Java annotations, request schemas in unsupported frameworks and full ORM query lineage are incomplete |
| Large repositories | File/byte budgets by depth, source classification, per-file content cache isolated by owner/repo, incremental diff, bounded evidence batches, AI cache | Full package rendering is repeated for version consistency; unchanged parsed files and AI batches are reused. Output for very large analyses needs performance validation |
| AI | Three SDK adapters, configurable models, retries/fallback, schema validation, citation existence checks, usage recording, no external calls by default | Citation existence is not semantic entailment; every AI finding remains inferred. Provider integration tests use doubles unless real credentials are supplied |
| Seven documents | Consistent IDs, versioned MD/DOCX/PDF, native XLSX RTM, requirements/UAT decisions, gaps | Generated cases are proposals requiring concrete fixtures; business stakeholder fields remain pending. PDF standard-font fallback can substitute unsupported glyphs |
| Diagrams | Evidence-labelled architecture and DFD 0/1/2, Mermaid/DOT and SVG/PNG with portable rendering | Graphs depict declarations and imports; unsupported runtime edges are omitted. Large graphs are bounded and complete edges remain in JSON |
| Tests and UAT | Unexecuted generated cases, reviewer-attested existing/manual evidence, optional container runner and JUnit counts, strict acceptance gate | Docker execution requires dedicated deployment validation. No automated mapping from repository tests to generated UAT cases; coverage percentages not invented |
| Review lifecycle | Authenticated reviewer allowlist, explicit per-analysis viewer/reviewer grants, comments, statement edits, baseline hashes, stale decision invalidation, immutable prior artifact versions, audit events | Multi-party quorum, regulated e-signatures, rich DOCX editing and external audit anchoring are not implemented |
| Persistence and jobs | SQLAlchemy SQLite local/PostgreSQL deployment, Alembic migrations, fakeredis local queue by default, configurable real Redis, local thread worker/Celery production, renewable worker leases, stale-job recovery, scheduler and retention | Distributed deployment and failure recovery still require live infrastructure acceptance; the local queue is process-scoped and intentionally not durable |
| Security | Opaque HTTP-only sessions, CSRF/origin checks, encrypted credentials, job ownership checks, safe downloads, known-secret redaction, no repository execution by default | Pattern redaction is not perfect. Data and backups need infrastructure encryption, quotas, endpoint rate limiting, monitoring and deployment review |

External integration acceptance should exercise a public repository, an authorized private/organization repository, OAuth callback and revocation, one request and a fallback on every configured model, PostgreSQL/Celery worker recovery, retention, encrypted backup recovery, and the dedicated test container. Those checks require services and credentials outside the local fixture.
